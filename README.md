# cobol-tools

Two Python tools for working with legacy COBOL systems — without touching the mainframe.

```
cobol-tools/
├── cobol_to_python/     # COBOL → Python translator
│   ├── translator.py    # core engine
│   ├── cobol2py.py      # CLI
│   └── examples/
│       └── payroll.cbl
└── cobol_db_bridge/     # COBOL flat file → database
    ├── bridge.py        # core engine
    ├── cobol_bridge.py  # CLI
    └── examples/
        └── employee.cpy
```

---

## The Problem

COBOL systems process an estimated **$3 trillion in transactions daily** — banking cores, payroll, government ledgers. The developers who built them are retiring. The organizations that run them need two things:

1. **Migration paths** — translate business logic out of COBOL into maintainable code
2. **Integration** — pipe COBOL data into modern databases, APIs, analytics

This repository addresses both.

## Tool 1 — COBOL to Python Translator

Converts COBOL source programs to idiomatic Python 3.

### What it handles

| COBOL | Python |
|---|---|
| `DATA DIVISION` working-storage | `@dataclass` with typed fields |
| `PIC 9(6)` / `PIC X(30)` / `PIC 9(4)V99` | `int` / `str` / `float` |
| `88`-level condition names | `@property` returning `bool` |
| `PERFORM paragraph` | function call |
| `PERFORM UNTIL condition` | `while` loop |
| `EVALUATE ... WHEN` | `match/case` (Python 3.10+) |
| `MULTIPLY a BY b GIVING c` | `c = a * b` |
| `ADD a TO b` | `b += a` |
| `SUBTRACT a FROM b GIVING c` | `c = b - a` |
| `COMPUTE x = expr` | `x = expr` |
| `MOVE x TO y` | `y = x` |
| `DISPLAY 'text' var` | `print("text", var)` |
| `STOP RUN` | `sys.exit(0)` |

### PIC clause mapping

```
PIC 9(6)      →  int    (6 digits)
PIC X(30)     →  str    (30 chars)
PIC 9(4)V99   →  float  (4 integer + 2 decimal digits)
PIC S9(7)V99  →  float  (signed)
PIC 9V999     →  float  (1 + 3 decimal)
```

### Usage

```bash
# Translate to stdout
python cobol2py.py payroll.cbl

# Write to file
python cobol2py.py payroll.cbl -o payroll.py

# Validate syntax of generated code only
python cobol2py.py payroll.cbl --validate
```

### Example

Input (`payroll.cbl`):
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PAYROLL.

       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-GROSS-PAY      PIC 9(6)V99.
       01  WS-TAX-RATE       PIC 9V999.
       01  WS-NET-PAY        PIC 9(6)V99.
       01  WS-EOF-FLAG       PIC X VALUE 'N'.
           88  END-OF-FILE   VALUE 'Y'.

       PROCEDURE DIVISION.
       MAIN-PARAGRAPH.
           PERFORM CALCULATE-PAY UNTIL END-OF-FILE.
           STOP RUN.

       CALCULATE-PAY.
           MULTIPLY WS-GROSS-PAY BY WS-TAX-RATE GIVING WS-NET-PAY.
           DISPLAY 'Net pay: ' WS-NET-PAY.
```

Output (`payroll.py`):
```python
"""
Auto-generated from COBOL program: PAYROLL
Generated by cobol-to-python translator
Review before use in production.
"""

import sys
from dataclasses import dataclass

@dataclass
class WorkingStorage:
    ws_gross_pay: float = 0.0
    ws_tax_rate: float = 0.0
    ws_net_pay: float = 0.0
    ws_eof_flag: str = ''

    @property
    def end_of_file(self) -> bool:
        return self.ws_eof_flag == 'Y'

ws = WorkingStorage()


def main_paragraph():
    while not (ws.end_of_file):
        calculate_pay()
    sys.exit(0)


def calculate_pay():
    ws.ws_net_pay = ws.ws_gross_pay * ws.ws_tax_rate
    print("Net pay: ", ws.ws_net_pay)


if __name__ == "__main__":
    main_paragraph()
```

## Tool 2 — COBOL DB Bridge

Reads COBOL fixed-length flat files using COPYBOOK definitions and loads them into a relational database or exports to CSV/JSON.

### What it handles

**File formats:**
- ASCII flat files (newline-separated or continuous)
- EBCDIC encoded files (`cp037`, IBM mainframe)

**COBOL data types:**
- `DISPLAY` — standard character/numeric fields
- `COMP-3` — packed decimal (IBM format, 2 digits per byte)
- `COMP` — binary (2/4/8 bytes, signed/unsigned)

**Targets:**
- SQLite (no dependencies)
- PostgreSQL (requires `psycopg2-binary`)
- CSV
- JSON

### Usage

```bash
# Preview schema and first 5 records
python cobol_bridge.py employees.dat employee.cpy --inspect

# Load to SQLite
python cobol_bridge.py employees.dat employee.cpy \
    --to sqlite:///employees.db \
    --table employees

# Load to PostgreSQL
python cobol_bridge.py employees.dat employee.cpy \
    --to postgresql://user:pass@localhost/payroll \
    --table employees

# Export to CSV
python cobol_bridge.py employees.dat employee.cpy \
    --to csv:///employees.csv

# EBCDIC file
python cobol_bridge.py mainframe.dat schema.cpy \
    --encoding cp037 \
    --no-newline \
    --to sqlite:///output.db
```

### Python API

```python
from bridge import parse_copybook, CobolFlatFileReader, load_sqlite

# Parse COPYBOOK
fields = parse_copybook(open('employee.cpy').read())

# Read flat file
reader = CobolFlatFileReader('employees.dat', fields, encoding='ascii')
records = reader.to_list()

# Load to SQLite
count = load_sqlite(records, fields, 'employees.db', table='employees')
print(f'Loaded {count} records')

# Or use the one-liner
from bridge import bridge
bridge('employees.dat', 'employee.cpy', 'postgresql://user:pass@host/db')
```

## COMP-3 Packed Decimal

IBM mainframes store numeric data as packed decimal (COMP-3) — 2 digits per byte, sign in last nibble. This format appears in virtually every banking COBOL system and is invisible to standard text parsers.

```
PIC 9(7)V99 COMP-3  →  5 bytes in file
Value 1234567.89  →  bytes: 12 34 56 78 9C  (C = positive)
Value -0000001.50 →  bytes: 00 00 00 15 0D  (D = negative)
```

The bridge handles this transparently — specify `COMP-3` in your COPYBOOK and the decoder does the rest.

## Limitations

**Translator:**
- Multi-line arithmetic (GIVING on next line) requires manual review
- EVALUATE with complex conditions may need adjustment
- File I/O stubs require implementation
- COBOL intrinsic functions not supported

**Bridge:**
- COMP-2 (floating point) not supported
- Variable-length records (VLR) not supported
- RDW (record descriptor word) files need preprocessing
